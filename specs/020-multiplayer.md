# 020 Online multiplayer (milestone 20)

Two friends play one versus one over the internet. The simulation is deterministic, so the browsers exchange only commands, in lockstep, through Azure Web PubSub; a small server function on the website hands out room tickets. Design and decisions: `docs/handoff/multiplayer.md`. Public lobbies, matchmaking, more than two players, AI players in online matches, reconnecting to a match and spectating are out of scope.

- **NET-1**: Rooms. On the Multiplayer panel a player hosts a room with the faction and map picked on the Single player panel, and is shown a six-character room code (no look-alike characters such as I, L, O, 0, 1) to share; their friend types the code and joins, and plays the other faction. The joining game asks the host until it is welcomed (once a second), is told when the room already has two players or the versions differ, and gives up after 20 s if nobody hosts the room. Once welcomed, both games start the same match (seed, map, factions from the host) in the same page, keeping the connection: the host is player 0, the guest player 1, each sees the match from their own side. The panel shows why online play is unavailable instead of its controls when the website's game server is missing or not configured, or in the desktop app; the rail marks Multiplayer "Unavailable" then. Hosting or joining can be cancelled while waiting.
- **NET-2**: Lockstep. Time is split into turns of 2 ticks (125 ms at the online game speed of ×0.8, UX-3). Each game announces its commands for turn `k` once its own simulation reaches turn `k − d`, where `d` is its input delay: 2 turns until the connection has been measured, then fitted to it. Every second each game sends a round-trip probe that the other answers at once; the delay is the slowest of the last 8 round trips, halved, plus 50 ms for jitter, in whole turns between 1 and 6 (on a good connection one turn, so an order takes effect 100 to 200 ms after it is given). Each game picks its own delay and may change it at any time, as only turn numbers are shared; sending the turn even when it holds no commands, and its own commands go through the same path as the opponent's; a turn reaches the simulation only when both players' commands for it have arrived, and is applied at the turn's first tick with player 0's commands first, each in the order issued. So both simulations apply exactly the same commands on the same ticks. Online matches run at normal speed: pause and speed keys only show a notice, and Escape opens a menu while the match goes on.
- **NET-3**: Desync detection. Every 60 ticks (3 s) each game sends a checksum of its whole simulation state; if the two differ for the same tick, both stop the match and say it went out of sync, naming the tick.
- **NET-4**: Disconnects. While the game is held up by the opponent for over a second it says it is waiting for them; after 5 s of silence it counts down. Thirty seconds without a message from the opponent (sixty before their game has sent anything, as it may still be loading) ends the match as a win for the player who stayed; an opponent closing or leaving the page says goodbye and the match ends at once as a win; a game that has ended in the simulation says goodbye with the tick it ended on, and that does not count as leaving: the other game, a few turns behind, plays on to the same end and shows its own result (15 s without getting there counts as the opponent leaving); losing one's own connection ends the match as "Connection lost". A match decided in the game shows the normal result screen, with only the main menu offered.
- **NET-5**: Security. Everything from the network is untrusted: a message must be well-formed JSON of a known type with fields of the right types and sizes (at most 32 commands a turn, 200 ids a list, 24 000 characters a message), or it is dropped; each command is rebuilt field by field with its player forced to the sender's seat, so a tampered game can only order its own side, and the simulation refuses the rest. Only messages from the welcomed opponent count; anyone else who asks to join is told the room is full. Room tickets come from the server function at `/api/negotiate`: it keeps the Web PubSub connection string in the website's app settings (never in the repository), validates room codes, gives each player a random user id, and signs a one-hour token that only lets that user publish to and be in that one room's group. The Content-Security-Policy allows connections only to the game's own origin and its Web PubSub host, and the offline cache never stores or answers API requests.
